Four panels, one window tree

The same BSP tiling tree drives a 480-pixel-tall ILI9488 and a 128×64 OLED. Nothing is special-cased per board. Pick a theme and watch every panel change at once. Gap, border, bar height and tab height are theme metrics too, so the tiles genuinely re-lay out — goldleaf’s wider gap costs the terminal three pixels. That is the Omarchy trick worth stealing: one file on the microSD reskins the whole system, no rebuild.

Why it tiles at all on a 2.4-inch screen

Real tiling past two panes on a 320×240 panel produces slivers nobody can read. So a split that cannot give both children the configured minimum tile size does not shrink them — it collapses into a tab group. The tree never changes; only the layout pass adapts. That single rule is what lets one window manager serve every screen in the drawer.

Room to split

Both children clear the minimum, so the split renders as a real side-by-side tile pair with the theme's gap between them.

So it tabs instead

The whole cramped subtree flattens into one tab strip. Every window stays reachable with super+tab, and the one you are using gets the full width.
